OWL-array is OWL 2 (OWL 2 Direct Semantics, OWL 2 Mapping to RDF Graphs) over the rdf-array data model, in which ( … ) is one term, a sequence, and () is the empty sequence. It changes two things and adds one small vocabulary:

Introduction

Definition, 2026-10-26; implemented in owlapi-array (OWL API 4.5.29, the 4.5 line that Protégé 5.6 loads), 2026-10-26; a worked example over FHIR RDF, examples/fhir, 2026-10-27; revised 2026-11-06: a sequence is an individual per occurrence, not identified by its elements, and ra:tupleOf names the sequences with given elements (§10 compares the alternatives and reports the experiments behind the choice). This document is owl-array.md in the organisation's meta-repository, rendered at <https://rdf-array.github.io/rdf-array/docs/owl-array.html>; rdf-array.md describes the change from RDF to rdf-array, and shacl-array.md settles the same questions for SHACL. The .claude/skills/owl-array skill in the same repository carries the implementation plan.

  1. OWL's own lists are sequences. The RDF mapping of OWL 2 spells the arguments of owl:unionOf, owl:intersectionOf, owl:oneOf, owl:members, owl:propertyChainAxiom, owl:hasKey, owl:disjointUnionOf, owl:withRestrictions and SWRL's swrl:body and swrl:head as RDF lists. Read with Turtle-array they are sequences, and a sequence is the only list: an rdf:first/rdf:rest ladder is triples (§2).
  2. A sequence in the data is an individual with built-in structure. ex:paper bibo:authorList ( ex:ada ex:alan ) holds one term. OWL-array reads that term as an individual of the class ra:Sequence whose members, length, first and last element are given by properties with a meaning the semantics fixes: ra:member, ra:memberValue, ra:length, ra:first, ra:last. Two sequences with the same elements are not thereby one individual; the class ra:tupleOf ( … ) picks out the sequences with given elements. Nothing about the term is asserted in triples, nothing is reserved vocabulary, and a class expression can constrain the members of a list-valued property while staying in OWL 2 DL (§3).

The second is the reason to do it. FHIR RDF writes a repeated element as a list, and its ontology could not say what the list holds; in OWL-array it says so with a restriction on a restriction:

PREFIX fhir: <http://hl7.org/fhir/>
PREFIX owl:  <http://www.w3.org/2002/07/owl#>
PREFIX ra:   <https://rdf-array.github.io/rdf-array/vocab#>

fhir:CodeableConcept rdfs:subClassOf
  [ a owl:Restriction ; owl:onProperty fhir:coding ;
    owl:allValuesFrom [ a owl:Restriction ; owl:onProperty ra:member ; owl:allValuesFrom fhir:Coding ] ] .

ex:cc fhir:coding ( [ fhir:system [ fhir:v "http://loinc.org"^^xsd:anyURI ] ; fhir:code [ fhir:v "8480-6" ] ] ) .

In Manchester syntax, fhir:coding only (ra:member only fhir:Coding). No construct in that axiom is new: the OWL API, Protégé's expression editor and every OWL 2 DL reasoner accept it today, treating ra:member as an ordinary object property. What is new is the meaning of ra:member, and of the ( … ) term in the data it constrains; from the two, a reasoner concludes that the blank node inside the list is a fhir:Coding. A worked example, the SWAT4LS 2016 FHIR reasoning process over today's FHIR RDF, is examples/fhir; OWL-array in Protégé is a demo of it in Protégé.

Why

OWL 2 DL reserves rdf:List, rdf:first, rdf:rest and rdf:nil for its own syntax. An ontology document whose data holds an RDF list leaves rdf:first triples unconsumed and is not OWL 2 DL (the mapping removes each triple a pattern matches, and the graph MUST be empty at the end), so BIBO's bibo:authorList and SKOS's skos:memberList push their users into OWL Full, and no DL class expression can look into a list at all. The workaround, since Drummond et al. 2006, has been to rebuild the ladder out of individuals under new names (a cell class, functional "contents" and "next" properties, a transitive "followed by"), as OWL-S's ObjectList and the Collections Ontology did. Its limits are well documented: the structure is open (nothing says a cell has no other successor), a fixed length cannot be stated without nesting one restriction per element, the "last" element needs a transitive property that no cardinality may use, and classification of 450-element lists took minutes. Every one of those limits comes from deriving a list's structure from triples. rdf-array makes the list a term; OWL-array gives the term a meaning.

Lists in OWL's syntax

Everywhere the RDF mapping of OWL 2 reads a list, OWL-array reads a sequence term:

Written in Turtle-array these are sequences already, so an OWL ontology written in Turtle reads unchanged. As in SHACL-array, three consequences follow:

  • A ladder is not a list. An ontology document that spells a list as rdf:first/rdf:rest triples (N-Triples written by an RDF 1.1 tool, say) leaves those triples unconsumed, exactly as a list in the data did before: the document is not OWL 2 DL and a parser reports the triples. Convert it first.
  • () is the empty list; rdf:nil is not. A SWRL rule with no body writes swrl:body (). owl:unionOf () is as ill-formed as it was.
  • Lists hold no blank-node structure. owl:unionOf ( [ a owl:Restriction ; … ] ) is a sequence holding a blank node whose own triples are ordinary triples of the document.

What a processor writes follows: the RDF renderers spell every OWL list as ( … ) in Turtle and as rdf:parseType="Collection" in RDF/XML, and never as a ladder. The Functional-style, OWL/XML and Manchester syntaxes have no RDF lists and are unchanged by this part.

Sequences in the data

Semantics

The direct semantics changes in one place; owl-array-semantics.md states it formally, as changes to the OWL 2 Direct Semantics, and owl-array-redline.html marks those changes in the Recommendation's own text. The object domain of an interpretation contains, beside the ordinary individuals, sequences: individuals each of which has a length n and an element at each position 1 … n, an element being an individual, a data value or a sequence. Each occurrence of a sequence term ( t1 … tn ) in an ontology denotes some sequence of length n whose i-th element is ti^I; an occurrence of () denotes some sequence of length 0. Consequently:

  • An occurrence is an anonymous individual whose structure is fixed. Two occurrences of ( 1 2 ), in one document or in two, may denote one sequence or two, and nothing in OWL-array says which, just as nothing says whether two blank nodes with the same description denote one thing. This is the rdf-array data model, in which each written ( … ) is a term of its own (rdf-array.md), and it agrees with RDF simple entailment, under which :s :p (1 2), (1 2) and :s :p (1 2) entail each other.
  • Elements tell sequences apart. Sequences of different lengths, or with different elements at some position, are different: occurrences of ( 1 2 ) and ( 1 3 ) denote different individuals in every interpretation, and occurrences of ( ex:a ) and ( ex:b ) do whenever ex:a owl:differentFrom ex:b.
  • Elements do not make sequences the same. Equal elements are necessary for two occurrences to denote one sequence, not sufficient. An ontology that wants identity by elements needs a construct for it that OWL 2 keys cannot supply (§10.1, B+K); §10 gives the design this replaces and the entailments each gives.
  • Sequences are a sort of their own. No IRI, blank node or literal denotes a tuple, so a sequence is never owl:sameAs an IRI-named individual, as a literal is not, and ra:Sequence is disjoint from every class of ordinary individuals.
  • A sequence is closed. Its members are exactly its elements, in order; there is nothing more to learn about them from other triples.

Where a sequence may stand in an ontology: wherever OWL 2 DL lets an anonymous individual stand. It may be the object of a property assertion, the individual of a class assertion, an element of another sequence, and an annotation value. OWL 2's restrictions on anonymous individuals keep it out of owl:hasValue, owl:oneOf, owl:sameAs, owl:differentFrom and negative property assertions, where an individual that no other axiom can name would say nothing useful. A class expression about a particular sequence uses ra:tupleOf instead: ex:rgb some ra:tupleOf ( 255 0 0 ) where an earlier draft wrote ex:rgb value ( 255 0 0 ). The link between a sequence and its elements is not an ObjectPropertyAssertion, so it does not count toward the forest condition on anonymous individuals in those restrictions. In RDF a sequence may only be an object, so an axiom that would need one as a subject has no RDF form and reaches an ontology only through the Functional-style, OWL/XML or Manchester syntax. A sequence is never a class, a property, a datatype or an ontology IRI. The RDF-based semantics (OWL 2 Full) is not addressed here.

The vocabulary

The ra: namespace, https://rdf-array.github.io/rdf-array/vocab#, holds the built-in entities of OWL-array. Like owl:Thing and owl:topObjectProperty, each has an extension the semantics fixes in every interpretation. An ontology uses them in class expressions and property axioms; it does not define them, and an axiom about one of them (a range on ra:member, say) constrains every sequence in the world, as an axiom about owl:topObjectProperty would.

TermKindIn every interpretation, for a sequence s
ra:Sequenceclassthe sequences, and nothing else
ra:memberobject propertys ra:member e for each element e of s that is an individual or a sequence
ra:memberValuedata propertys ra:memberValue v for each element v of s that is a literal
ra:lengthfunctional data propertys ra:length n, n the number of elements of s, an xsd:nonNegativeInteger
ra:first, ra:lastfunctional object propertiesthe first and the last element of s, when it is an individual or a sequence
ra:firstValue, ra:lastValuefunctional data propertiesthe first and the last element of s, when it is a literal
ra:tupleOf ( c1 … cn )class expressionthe sequences s of length n whose i-th element is in ci, where ci is a class expression, a data range, an individual (that individual) or a literal (that value)

ra:tupleOf is the one new constructor. Its positions are exact, since a sequence is closed: ra:tupleOf ( 255 0 0 ) holds ( 255 0 0 ) and not ( 255 0 0 7 ). In RDF, an IRI element of its list is a class when the imports closure declares it owl:Class, a datatype when it declares it rdfs:Datatype, and an individual otherwise, the way the RDF mapping of OWL 2 already uses declarations to tell entities apart. A literal element is that value, and a blank node element is a class expression or data range given by its own triples.

ra:first ⊑ ra:member, ra:last ⊑ ra:member, ra:firstValue ⊑ ra:memberValue and ra:lastValue ⊑ ra:memberValue hold by construction; so does ∃ra:member.⊤ ⊑ ra:Sequence and the like for every property above. Three classes are definable and are defined, with the declarations and these axioms, in the vocabulary ontology vocab/owl-array.ttl, which an ontology may import so that an editor knows the entities:

ClassDefinition
ra:EmptySequencera:Sequence and ra:length value 0, the class of ()
ra:ObjectSequencera:Sequence and not (ra:memberValue some rdfs:Literal): no literal members
ra:DataSequencera:Sequence and not (ra:member some owl:Thing): no individual members

The vocabulary ontology is plain OWL 2 DL and says the same thing read as RDF 1.1 or as rdf-array. Importing it is a convenience, not a requirement: the meaning of the built-ins does not come from its axioms.

The use cases of §1, in Manchester syntax, with the Turtle-array of the first:

    ex:Paper rdfs:subClassOf
      [ a owl:Restriction ; owl:onProperty bibo:authorList ;
        owl:allValuesFrom [ a owl:Restriction ; owl:onProperty ra:member ; owl:allValuesFrom foaf:Agent ] ] .
    
    ex:p a ex:Paper ; bibo:authorList ( ex:ada ex:alan ex:grace ) .

The two quantifiers stay separate: bibo:authorList only (ra:member only C) says every author of every author list is a C; bibo:authorList some (ra:member some C) says some list has some C; bibo:authorList only (ra:member some C) says every list has one. A property chain through ra:member or ra:first gives an existing vocabulary a view of the list: with the chain above, ex:p dc:creator ex:ada is entailed, and every class expression ever written over dc:creator applies to list members. Such a chain makes its super-property non-simple, so dc:creator can no longer appear in a cardinality restriction; that is OWL 2's usual rule.

Entailments

From the ontology above, a reasoner that implements OWL-array (§6) concludes:

  • ex:ada a foaf:Agent, ex:alan a foaf:Agent, ex:grace a foaf:Agent;
  • ex:p a ex:BigPaper, since ( ex:ada ex:alan ex:grace ) ra:length 3;
  • ex:p dc:creator ex:ada, ex:p ex:firstAuthor ex:ada;
  • ( ex:ada ex:alan ex:grace ) a ra:Sequence, ra:ObjectSequence, and not ra:EmptySequence;
  • ex:p a ex:AdaFirst, and, if ex:ada owl:sameAs ex:adaL, ex:p a (bibo:authorList some ra:tupleOf ( { ex:adaL } ex:alan ex:grace ));
  • ex:ring a ex:Ring with three points is inconsistent, and ex:red ex:rgb ( 255 0 ) with ex:red a ex:Swatch is inconsistent;
  • ex:x ex:rgb ( 255 0 0 ) entails ex:x a ex:RedThing, whichever document each comes from;
  • ex:x ex:rgb ( 255 0 0 ) . ex:y ex:rgb ( 0 0 255 ) entails that the two sequences are different individuals; ex:x ex:rgb ( 255 0 0 ) . ex:y ex:rgb ( 255 0 0 ) entails neither that they are the same nor that they are different.

Nothing follows about the members of a list from the list alone: ( ex:ada ex:alan ) says that ex:ada is a member of it and nothing more, as a triple says nothing more than itself.

Counting, and literal members

Two consequences of OWL 2's semantics are worth knowing before writing cardinalities:

  • ra:member counts distinct individuals, not positions. ( ex:a ex:a ex:a ) has one member, and ( ex:a ex:b ex:c ) has three only in interpretations where the three are different, which OWL does not assume. "At least three authors" is ra:length some xsd:integer[>= 3], which is crisp; "three different authors" adds ra:member min 3 foaf:Person to it. The same holds for ra:memberValue and repeated literals.
  • ra:member only C says nothing about literal members. It is vacuously true of ( 1 2 3 ). To require that every element is an individual in C, write ra:ObjectSequence and ra:member only C; for literals, ra:DataSequence and ra:memberValue only D.

Profiles

OWL 2 EL has no only, so an EL ontology constrains members through a property chain and a range: bibo:authorList o ra:member SubPropertyOf: ex:author, ex:author Range: foaf:Agent. OWL 2 RL keeps only over members in superclass position, which is where the examples above use it, and has no datatype facets, so length bounds are outside RL. ra:tupleOf expands to an intersection of some and value restrictions (§6), which EL allows anywhere and RL allows on the left of SubClassOf; telling two sequences apart by their elements needs the expansion's functional position properties, which EL has only for data. The vocabulary ontology uses functional object properties, complements and unions, which EL and QL lack; an EL or QL ontology relies on the built-in meaning without importing it.

What OWL-array does not add

  • No ladder reading. rdf:first/rdf:rest triples are triples in OWL's syntax and in the data, and leave an ontology outside OWL 2 DL as they always did. OWL-array does not fold them.
  • No ra:rest. A property to the sequence of the remaining elements would rebuild the ladder as individuals, with every limit of §1: it is left out on purpose. ra:first and ra:last cover the positions ontologies ask for; the remaining ones are reached, for now, by SPARQL-array's position patterns rather than by class expressions.
  • No content model. ra:tupleOf fixes the length; a regular content model over members (( Person+ Org? )) is the natural next layer, as it is for SHACL-array and ShEx-array.
  • No positional properties in the vocabulary. The expansion (§6) has a property per position; they stay out of ra:, for the reasons of §10.3.
  • No datatype reading. A literal-only sequence is still an individual with ra:memberValues, not a value of a sequence datatype. OWL 2 DL keeps individuals and data values apart, and a datatype could never say "every author is a Person"; one reading is simpler than two.
  • No counting by position through ra:member (§3.5), and no uniqueness constraint: SHACL 1.2's sh:uniqueMembers has no OWL-array counterpart, since OWL cannot say that two positions differ.
  • No identity by elements, unless an ontology states it (§3.1, §10). A sequence has no IRI and no label; an editor displays it by its spelling.

Reasoning with a reasoner that does not know sequences

The semantics of §3 is normative; how a reasoner meets it is not. The first implementations give an existing OWL 2 DL reasoner (HermiT, JFact, ELK for EL) the meaning of the built-ins by expansion: a decorator around the reasoner rewrites the ontology it sees, and nothing is added to the ontology the user edits or saves. For each occurrence s of a sequence term in the imports closure, with elements e1 … en:

  • s becomes a fresh named individual. Naming an anonymous individual (Skolemising it) keeps every entailment that does not mention the new name, and the decorator maps results back to the occurrence, so no name leaves the expansion. Since the name does not depend on the elements, an occurrence holding a blank node is named like any other. Whether the blank nodes inside should be named the same way, so that ra:member can be closed with a ObjectOneOf of them, is rdf-array#20; FHIR RDF, in which every element is a blank node, is the case that decides it.
  • ClassAssertion( ra:Sequence s ) and DataPropertyAssertion( ra:length s n ).
  • Positions: ObjectPropertyAssertion( o_i s ei ) for an individual or sequence element and DataPropertyAssertion( d_i s vi ) for a literal, where o_i and d_i are functional properties with domain ra:Sequence, private to the expansion; and ClassAssertion( ObjectMaxCardinality( 0 o_n+1 ) s ) with its data counterpart, so that nothing follows position n.
  • ObjectPropertyAssertion( ra:member s ei ) for each individual element and DataPropertyAssertion( ra:memberValue s vi ) for each literal element, with ra:first, ra:last, ra:firstValue and ra:lastValue for the ends.
  • Closure: ClassAssertion( ra:member only { the individual elements } s ), or ra:member max 0 when there are none, and the same for ra:memberValue with a DataOneOf. Closure is what makes ra:member only C decidable on s and what no ladder could supply; it is omitted for an EL reasoner, which cannot express it and cannot ask the questions that need it.
  • Nested sequences are expanded recursively, each occurrence to its own individual.
  • ra:tupleOf ( c1 … cn ) becomes ra:Sequence and ra:length value n intersected, for each i, with o_i value a (an individual a), o_i some C (a class expression, or a nested ra:tupleOf), d_i value v (a literal) or d_i some D (a data range). This is the structural expansion.
  • Hybrid expansion of ground tuples. A reasoner pays heavily for structural ra:tupleOf classes (§10.4). For each ra:tupleOf whose elements are all individuals and literals, the expansion therefore makes a named class T, adds T SubClassOf its structural expansion, puts T where the ra:tupleOf was, and asserts ClassAssertion( T s ) for each occurrence s whose elements are those individuals and values, comparing literals by value. This is sound. It is complete when the elements are literals, whose identity the expansion can decide. With individual elements it misses an occurrence whose elements are only entailed to be the tuple's (through owl:sameAs or a functional property); a query written with the structural form still finds it.

The expansion is linear in the number of elements, complete for the sequences spelled in the ontology (with the hybrid's exception above), and sound for the rest: of a sequence that a class expression merely asserts to exist, a reasoner knows what the vocabulary ontology's axioms say. The vocabulary ontology is added to the closure the reasoner sees. Reasoner results that mention expansion individuals are mapped back to sequence terms on the way out.

Decisions and precedent

  • An individual, not a data value, and not syntax only. The datatype alternative (§5) could not reach IRI or blank-node members; leaving data sequences unread would have left the motivating cases out. The individual reading is the only one that lets a class expression say "every author is a Person".
  • Built-in properties, not a new restriction kind. owl:onPropertyMembers, a restriction whose allValuesFrom applied to the members of a property's values, was considered. It fuses two quantifiers (every value, every member) and would need new class expressions in every syntax, parser, renderer and reasoner interface. Nesting an ordinary restriction on ra:member needs none of that, composes with property chains, and matches SHACL 1.2's sh:memberShape plus sh:minListLength, ShEx-array's ((S))[m, n], JSON Schema's items plus minItems, and the array types of property-graph schemas (Neo4j's LIST<INTEGER NOT NULL> constraints, PG-Schema's STRING ARRAY {1,2}): a constraint on members and bounds on length.
  • No IRI, and no identity by elements. The first draft named each sequence with a reversible URN and an rdfs:label, which made ( ex:a ) and ( ex:b ) different individuals even when ex:a owl:sameAs ex:b. The second (2026-10-26 to 2026-11-05) made a sequence denote the tuple of its elements, so that equal sequences were one individual everywhere. The rdf-array data model then made each written ( … ) a term of its own (2026-11-03), and that reading made OWL entail more than the data model: :N1 :p (1 2) . :N2 :p (1 2) entailed that N1 and N2 have a common :p value. This revision gives up identity by elements, keeps every OWL 2 inference, and gets RedThing back with ra:tupleOf. §10 has the alternatives and the evidence.
  • No companion ontology. The same draft materialised the ra: assertions into an ontology imported beside the source. The length of ( 1 2 3 ) is a fact about the term, as the value of "3"^^xsd:integer is; it is computed where it is needed, not stored.
  • No ra:rest, for the reasons of §5.
  • Precedent for description logic over sequences is thin and all of it builds proxies: Drummond et al. (2006), who also showed regular-expression-like matching over classes of lists by nesting; the Collections Ontology with indexed co:ListItems; the ontology design patterns' Sequence pattern. The theory that bears on OWL-array is Baader and Sattler's on aggregates (a built-in ra:length on a closed term avoids the undecidability of counting over open chains), Lutz, Areces, Horrocks and Sattler's on keys (identity by elements, where an ontology wants it, is a key on positions, decidable over named individuals), and temporal description logics over finite traces for the content-model layer to come. Property graphs have arrays only of primitive values and constrain them by element type and count; none lets an array hold a node, which is the case that matters here.

Identity: the alternatives

When do two sequences denote one individual? The answer decides what follows from data that two documents wrote separately. It also decides whether OWL-array entails more than the rdf-array data model it sits on, and what a reasoner pays. This section sets out the designs considered, the entailments on which they differ, and the experiments behind §3.1's choice.

The designs

  • O. OWL 2 as it is. A list in the data is an RDF 1.1 list: a blank node with rdf:first and rdf:rest triples. The baseline: what an ontology gets today.
  • A. Identity by elements (OWL-array from 2026-10-26 to 2026-11-05). A sequence term denotes the tuple of its elements' denotations, so equal sequences are one individual in every document, as a literal denotes one value. A sequence may be a nominal: ex:rgb value ( 255 0 0 ). The expansion gives each distinct ground sequence one named individual.
  • B. One individual per occurrence (this document, §3.1). Each occurrence denotes some sequence with its elements; equal elements do not make two the same. ra:tupleOf replaces the nominal. The expansion is structural or hybrid (§6).
  • B+K. B with identity on request. An ontology that wants identity by elements asks for it. An OWL 2 key cannot do this: keys bind only individuals in NAMED, and a sequence is never named (owl-array-semantics.md §2.3.5). The experiment in §10.4 got the identity from HasKey( ra:Sequence ( o_1 … ) ( ra:length d_1 … ) ) only because the expansion names every occurrence, which the semantics does not. So B+K needs a built-in of its own, one that equates sequences with the same length and elements, at least when those elements are named.
  • D. A datatype. A sequence of literals is a data value of a sequence datatype, equal by value for free. It cannot hold an individual, so "every author is a Person" is out of reach; §9 rejects it.
  • E. Positional properties in the vocabulary. B, with the expansion's position properties made public (ra:o_1, ra:d_1, …, after RDF's rdf:_1, rdf:_2, …), so that an ontology writes tuple classes and keys itself instead of ra:tupleOf. Its entailments are those of B, or of B+K with a key.

The list's head is a blank node, so the restriction names an anonymous individual, which OWL 2 DL forbids in ObjectHasValue (OWL 2 Syntax §11.2). The OWL API takes it anyway: it drops the rdf:first/rdf:rest triples, reports no unparsed triples, and its OWL 2 DL profile checker passes the ontology, a gap in the checker. Read that way, the two lists are two anonymous individuals, even in one document, and nothing makes them one. The RDF-Based Semantics has no extensionality for lists either, so OWL 2 Full does not equate them, and Jena's rules agree. The named individual works because both axioms name the same thing. A literal works for the same reason: it denotes its value in every interpretation, which is what design A gave sequences.

Reasoning cost

K classes Ci ≡ ex:rgb some ra:tupleOf ( i i+1 i+2 ) and n individuals each with one ex:rgb sequence drawn from those K. The measure is the time to retrieve the instances of all K classes after a consistency check. "Structural, shared" gives one individual to all equal sequences, which is design A's identity with B's classes. "Nominal" is a stand-in for design A's expansion, a named individual per distinct sequence with Ci ≡ ex:rgb value ci, without the ra: assertions.

Open

  • How an ontology asks for identity. It needs a built-in, since an OWL 2 key does not reach sequences. That could be one assertion (ra:Sequence a ra:KeyedByElements, say) whose semantics equates sequences with equal lengths and elements, and which the expansion turns into the key of T4. Design E's public positions would not be enough, for the same reason.
  • Completeness of the hybrid expansion with individual elements: whether to fall back to the structural form for a tuple whose elements take part in owl:sameAs, functional properties or keys, and what that costs.
  • Other reasoners (ELK, JFact, Pellet, Konclude), and the cost of B+K's key at scale.
  • OWL 2 Full. The RDF-Based Semantics is not addressed (§3.1). Design B needs no extensionality condition there, where design A would have needed one.
