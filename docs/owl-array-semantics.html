This document gives the model theory of OWL-array as changes to the OWL 2 Direct Semantics, for a reader who knows that specification. It follows that document's section numbers, and each heading links to the section it changes. Only changes to the interpretations or to what is entailed are marked, in boxes. Unchanged text is not repeated, and a section that is not mentioned is unchanged. The examples extend the running Griffin family examples of the OWL 2 Structural Specification with one ordered list. 2026-11-06; the design and the alternatives it was chosen from are in owl-array.md §3 and §10.

Introduction

Introduction: the running example

Five axioms. Three come from the Structural Specification's examples, and two are new. One new axiom holds a list, Peter's children from eldest to youngest. The other connects the list to a:fatherOf, the property of the §9.6.2 example:

SameIndividual( a:Meg a:Megan )                                   # Structural Spec. §9.6.1
  DifferentIndividuals( a:Peter a:Meg a:Chris a:Stewie )            # §9.6.2
  ClassAssertion( a:Boy a:Stewie )                                  # §9.1.3
  ObjectPropertyAssertion( a:children a:Peter ( a:Meg a:Chris a:Stewie ) )        # new
  SubObjectPropertyOf( ObjectPropertyChain( a:children ra:member ) a:fatherOf )   # new

Call this ontology OG. In Turtle-array the fourth axiom is a:Peter a:children ( a:Meg a:Chris a:Stewie ) .. Read as RDF 1.1, its list is an rdf:first/rdf:rest structure that OWL 2 DL does not admit in data, which is where OWL-array starts.

The syntax this assumes, from owl-array.md §4:

  • A sequence term ( t1 … tn ), n ≥ 0, is an Individual, and each ti is an individual (named, anonymous or another sequence term) or a literal.
  • ObjectTupleOf( u1 … un ) is a class expression, and each ui is a class expression, a data range, a named individual or a literal.
  • Seven built-in entities have fixed meanings, as owl:Thing has: ra:Sequence, ra:member, ra:first, ra:last, ra:memberValue, ra:length, ra:firstValue and ra:lastValue.

The entailments below were checked with HermiT 1.4.3 through the expansion of owl-array.md §6 (Family.java in examples/owl-identity). That expansion gives evidence, not a proof. The claims follow from the definitions.

Direct Model-Theoretic Semantics for OWL 2

Vocabulary

VI also contains every sequence term, and each occurrence of a sequence term is an anonymous individual of its own. Two occurrences of ( a:Meg a:Chris a:Stewie ) are two members of VI, as _:x and _:y are. VC contains ra:Sequence; VOP contains ra:member, ra:first and ra:last; VDP contains ra:memberValue, ra:length, ra:firstValue and ra:lastValue. The datatype map contains xsd:nonNegativeInteger.

Most of what follows comes from this one decision. Because a sequence term is anonymous, §2.3.7 standardizes its occurrences apart and §2.4 lets a model reinterpret them. Nothing makes two of them equal because their elements are.

Interpretations

An interpretation also has a set SEQ ⊆ ΔI of sequences, a function len from SEQ to the non-negative integers, and a function el that gives, for each x ∈ SEQ and 1 ≤ i ≤ len(x), an element el(x, i) ∈ ΔI ∪ ΔD. These conditions hold:

  • for each sequence term s = ( t1 … tn ) in VI: (s)I ∈ SEQ, len((s)I) = n, and el((s)I, i) is (ti)I when ti is an individual and (ti)LT when it is a literal;
  • (a)I ∉ SEQ for each individual a, named or anonymous, that is not a sequence term: sequences are a sort of their own, as data values are;
  • (ra:Sequence)C = SEQ;
  • (ra:member)OP = { (x, el(x, i)) | x ∈ SEQ, el(x, i) ∈ ΔI }, and (ra:memberValue)DP is the same with ΔD;
  • (ra:first)OP and (ra:last)OP are the same with i = 1 and i = len(x), and likewise for ra:firstValue and ra:lastValue;
  • (ra:length)DP = { (x, len(x)) | x ∈ SEQ }.

Nothing requires two sequences with the same len and el to be one element of SEQ. Sequences are not extensional. The converse does hold, because len and el are functions: two sequences that differ in length, or in the element at some position, are different elements of ΔI.

In every model of OG, Peter's a:children value is a sequence x with len(x) = 3 and el(x, 1) = (a:Meg)I = (a:Megan)I. Since a:Meg ≠ a:Chris, x differs from every sequence whose first element is Chris, such as the value of ( a:Chris a:Meg a:Stewie ). OWL-array cannot say so with DifferentIndividuals (§2.3.6), but every model makes the two different.

The built-ins give the first entailments over the list.

An individual inside ObjectTupleOf must be named, as one inside ObjectHasValue must (Structural Spec. §11.2). So ObjectTupleOf is how a class expression mentions a particular sequence, and a sequence term itself never appears in a class expression.

Compare the end of Structural Spec. §9.6.2. There, FunctionalObjectProperty( a:fatherOf ) makes the example inconsistent, because Meg, Chris and Stewie would have to be one individual. A functional a:children is consistent, because one sequence holds all three.

Datatype Definitions

Unchanged.

Keys

Table 9 is unchanged, but it no longer reaches sequences. A sequence is never the interpretation of a named individual, so in some model none is in NAMED. A key therefore never entails that two sequences are equal, and never identifies two individuals through a sequence-valued key property. To get identity by elements, an ontology needs a construct of its own. owl-array.md §10.5 leaves that construct open.

Assertions

Table 10 is unchanged. Because a sequence term is an anonymous individual, Structural Spec. §11.2 keeps it out of SameIndividual, DifferentIndividuals and the negative property assertions, and out of ObjectOneOf and ObjectHasValue. The link between a sequence and its elements is not an ObjectPropertyAssertion, so it adds no edge to §11.2's forest condition.

Ontologies

The axiom closure is satisfied with anonymous individuals and sequence terms standardized apart. Every occurrence of a sequence term in the closure is a distinct anonymous individual. That includes two occurrences in one axiom and occurrences in different imported ontologies. A structurally equal axiom stated twice is still one axiom, so it adds no second occurrence.

Here OWL-array departs from treating a sequence like a literal, the design owl-array.md §10 calls A. A sequence is like a blank node with a fixed description. Two of them are not entailed to be one thing, and not entailed to be two. This agrees with RDF simple entailment over the same data, and with OWL 2, which entails nothing about two RDF 1.1 lists here because they are anonymous individuals (owl-array.md §10.4.1).

Inference Problems

Unchanged. Instance checking and the atoms of a Boolean conjunctive query name only named individuals, so a question about a sequence is asked through the property that holds it, as in the tables above. §2.5's restriction to simple properties in cardinalities applies as before; a chain through ra:member makes its super-property non-simple (§2.2 above).

Independence of the Direct Semantics from the Datatype Map

Unchanged. Overall, the datatype map changes only by requiring xsd:nonNegativeInteger; Tables 1, 3 and 5 to 10 and the definitions of §2.4 and §2.5 are unchanged. The RDF-Based Semantics is not addressed. Under it, design B needs no extensionality condition for sequences. Design A would have needed one.
